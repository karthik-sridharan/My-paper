\section{Architecture}
\laiold{The browser stores a canonical project object and sends that object to a trusted backend for compilation or AI assistance. The editor, compiler, preview, sync, and AI pieces communicate through provider contracts instead of direct cross-module calls.}\lai{%
The architecture centers on a structured, versioned project object that resides within the browser. This canonical project object encapsulates the current state, including document content, metadata, and version history, supporting incremental updates and collaborative editing. The browser transmits this object to a trusted backend for compilation or AI assistance. Communication between the editor, compiler, preview, sync, and AI modules occurs through well-defined provider contracts, which abstract implementation details and facilitate modularity. This design ensures that each component interacts with the project data in a decoupled, flexible manner, enabling seamless updates and extensions.
}

\section{A Result}
\begin{theorem}[Foundation seam]
If each subsystem is hidden behind a provider interface, then browser-only mode, backend compile mode, and later real-time collaboration can share the same project format.
\end{theorem}

\begin{proof}
The project is represented by stable file paths and ids. UI events update the project state, and providers consume snapshots of that state. Replacing a provider changes implementation details but not the document model.
\end{proof}
